# 理赔查勘台

面向地下车库无信号场景的查勘定损演示系统：派单抢领、离线车损登记、联网合并留两版、保单批改联动作废重算、流转强校验、关开续办。

零外部依赖，Node.js 内置 `http` + JSON 文件原子写（临时文件 + `rename`）持久化。

## 运行

```bash
npm start            # http://localhost:8080
npm test             # 12 项自动化测试（node:test）
```

## 四个工作台

| 页签 | 能力 |
|---|---|
| ① 派单领取 | 领取案件；可切换查勘员身份，或一键「模拟两人同时领取」 |
| ② 现场查勘 | 勾选车损部位 + 估损金额；切「离线」后登记只进本机队列，可继续查看已拉取台账 |
| ③ 定损与流转 | 最终化定损结论、提交审批；作废结论会给出重算算式并拦截流转 |
| ④ 公司台账/保单 | 内勤侧补录车损（与现场版并列）、保单批改（触发批量作废重算） |

右上角切换查勘员（陈晨 / 周海），建议开两个浏览器窗口分别登录，演示真实抢单与联动。

## 推荐演示路径（对照需求逐条验收）

1. **抢单**：在「派单领取」点「⚡ 模拟两人同时领取」——两个请求同批发出，
   先到者 200 acquired，后到者收到 409 并明确显示**被谁、何时领走**。
   （自动化：200 并发请求压测恰好 1 人成功）
2. **离线登记 → 合并留两版**：领单后切「离线」，在现场页登记车损（只进本机队列）；
   到「公司台账」页需先切回在线写入一版台账修改；再次切离线……恢复网络后点
   「同步离线登记」。同一案件两边都改时，版本区出现橙色提示，现场版/台账版按登记时间
   交错排列、互不覆盖。重复回放按 `clientId` 幂等去重。
3. **保单更新联动**：在台账页把保单比例/免赔改掉，所有在途的「最终结论」立即变
   「已作废」并给出按新条款的重算算式，案件退回查勘中。
4. **过期结论不能流转**：不重新确认重算就点「提交审批结案」，服务端返回 409 并列明
   原因（已作废 / 草稿 / 保单版本过期）。
5. **关掉再打开接着办**：离线队列、表单草稿、当前身份都在 localStorage；
   服务端台账落盘 `data/db.json`，重启后领取归属、车损版本、作废状态原样恢复
   （`test/persistence.test.js` 覆盖）。

## 定损算式

```
建议赔付 = 估损金额 × 赔付比例 − 每次免赔额（不低于 0）
```

最终化永远以「最新车损版本 + 最新保单版本」计算，从机制上杜绝用旧依据出结论。

## API 摘要

| 接口 | 说明 |
|---|---|
| `POST /api/cases/claim` | 原子领取；冲突返回 409 + 领取人/时间；本人重复领取幂等 |
| `POST /api/cases/:no/damage` | 追加车损版本（source=field/ledger），新版本可作废旧结论 |
| `POST /api/sync` | 离线队列批量回放，按 `clientId` 幂等去重，单条失败不阻塞其它 |
| `POST /api/cases/:no/finalize` | 作废结论经人工确认后按新依据重新最终化 |
| `POST /api/cases/:no/approve` | 流转强校验：非最终态/保单版本过期一律 409 |
| `POST /api/policies/:no` | 保单批改升版本，批量作废在途结论并重算（已结案不翻案） |
| `GET /api/state` / `POST /api/reset` | 台账快照 / 重置演示数据 |
