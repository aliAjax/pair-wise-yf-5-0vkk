# 理赔查勘台

离线优先的理赔查勘工作台：现场查勘员在地下车库等无信号场景下登记车损部位与估损金额，恢复网络后与公司台账合并；支持领取并发抢占、冲突两版保留、保单更新触发定损结论作废重算、案件流转拦截。

## 运行

```bash
npm install
npm start
# 访问 http://localhost:3000
```

## 核心功能与演示路径

### 1. 领取案件（并发抢占）
- 案件列表中点击「领取案件」。
- 两人同时领取同一案件：先到者拿到，后到者看到「已被 XXX 领取」。
- 后端通过同步「检查-设置」保证原子性（Node 单线程模型下无竞态）。

### 2. 离线登记车损（无信号场景）
- 在案件详情中添加车损部位、填写估损金额，保存。
- 离线时数据保存在 IndexedDB，标记「待同步」。
- 恢复网络后自动同步到公司台账。

### 3. 台账合并（冲突两版）
- 同一案件两边都修改过（本地离线改 + 公司台账改），同步时检测到 `base_version` 不一致。
- 不强制合并，按时间保留两版（本地版 + 公司台账版），当前显示最新时间版本。
- 案件详情中「版本历史（两版）」可查看。

### 4. 保单更新 → 定损结论作废重算
- 保单管理中更新保单条款（如车损险保额）。
- 该保单项下所有定损结论自动作废（`valid=false`），并按新条款重算。
- 案件详情显示「结论已作废 · 重算金额 XXX」，确认后结论重新有效。

### 5. 案件流转拦截
- 定损结论作废或待确认重算时，「流转至定损/完成案件」按钮禁用。
- 后端流转接口同样拦截，返回 `assessment_invalid`。

### 6. 持久化（关掉再打开接着处理）
- 所有案件、定损、变更队列、同步记录保存在 IndexedDB。
- 查勘员身份保存在 localStorage。
- 关闭浏览器再打开，自动恢复上次状态，继续处理。

## 架构

```
server/
  index.js      # Express API 服务
  store.js      # 数据存储 + 业务逻辑（领取/流转/保单更新/同步/重算）
  data.json     # 数据文件（自动生成）

public/
  index.html    # 页面结构
  styles.css    # 样式
  db.js         # IndexedDB 本地存储封装
  sync.js       # 同步管理器（变更队列/冲突合并/拉取）
  app.js        # 主应用（UI 渲染/交互/在线离线）
  sw.js         # Service Worker（应用外壳离线缓存）
```

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/users | 查勘员列表 |
| GET | /api/cases | 案件列表（含领取人/保单/定损） |
| GET | /api/cases/:id | 案件详情 |
| POST | /api/cases/:id/claim | 领取案件（原子抢占） |
| POST | /api/cases/:id/flow | 案件流转（拦截过期结论） |
| POST | /api/assessments | 新建定损 |
| POST | /api/assessments/:id/confirm-recalculation | 确认重算结果 |
| GET | /api/policies | 保单列表 |
| PATCH | /api/policies/:id | 更新保单（触发作废重算） |
| POST | /api/sync | 离线变更同步（冲突两版合并） |
| POST | /api/reset | 重置数据（演示用） |

## 数据模型

- **案件 Case**: 案号、状态（待领取/已领取/查勘中/定损中/已完成）、领取人、保单、版本号
- **定损 Assessment**: 车损部位、估损金额、核定金额、结论、保单版本、有效标志、重算结果、历史版本
- **保单 Policy**: 保单号、险种保额、版本号
- **同步队列**: 本地变更（类型/服务端ID/基线版本/数据/时间戳）
